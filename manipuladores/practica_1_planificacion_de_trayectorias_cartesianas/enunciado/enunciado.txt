================================================================================
1. OBJETIVO DE LA PRACTICA
================================================================================

La practica consiste en generar trayectorias cartesianas para un manipulador de
6 GDL en ROS 2 Humble. Se trabaja en dos niveles:

1. Interpolacion cartesiana entre dos poses:
   - posicion con interpolacion lineal
   - orientacion con quaterniones mediante slerp

2. Trayectoria suavizada entre tres poses P0 -> P1 -> P2:
   - se evita la discontinuidad de velocidad en P1
   - se aplica un suavizado tipo Taylor en la zona de transicion
   - cada pose cartesiana se convierte despues a espacio articular con IK (KDL)

El controlador final del robot es articular por posicion.

================================================================================
2. FUNDAMENTO TEORICO
================================================================================

2.1. Interpolacion cartesiana

- La posicion se interpola linealmente en el espacio cartesiano.
- La orientacion se interpola con quaterniones.
- En la practica se pide implementar manualmente slerp, aunque `tf2` ya incluye
  una implementacion propia.

2.2. Suavizado entre dos tramos rectilineos

Al concatenar el tramo P0 -> P1 con el tramo P1 -> P2 aparece una
discontinuidad de velocidad en P1. Para evitarlo, se define una zona de
transicion de anchura temporal `2*tau` alrededor de P1 en la que la velocidad
cambia suavemente.

La posicion suavizada viene dada por:

  p(t) = p1 - ((tau - t)^2 / (4*tau*T1)) * Delta_p1
             + ((tau + t)^2 / (4*tau*T2)) * Delta_p2

La orientacion suavizada se define como:

  q(t) = q1 * q[ -((tau - t)^2 / (4*tau*T1)) * theta1, n1 ]
            * q[  ((tau + t)^2 / (4*tau*T2)) * theta2, n2 ]

Interpretacion de parametros:
- `tau`: intervalo de transicion alrededor de P1
- `T`: tiempo total usado en la practica para recorrer el tramo
- `t`: instante actual dentro del bucle temporal

10. EJERCICIO 1: INTERPOLACION CARTESIANA
================================================================================

Implementar:

  std::pair<tf2::Vector3, tf2::Quaternion>
  PoseInterpolation(const Eigen::Matrix4d &start_pose,
                    const Eigen::Matrix4d &end_pose,
                    double lambda)

Requisitos:
- `lambda` pertenece a [0, 1]
- interpolacion lineal de la posicion
- interpolacion slerp de la orientacion
- devolver:
  - `tf2::Vector3 p_interp`
  - `tf2::Quaternion q_interp`

El codigo de comprobacion llama a:
- `PoseInterpolation(pose0, pose1, 0.0)`
- `PoseInterpolation(pose0, pose1, 1.0)`
- `PoseInterpolation(pose1, pose2, 0.0)`
- `PoseInterpolation(pose1, pose2, 1.0)`

Por tanto:
- `p0, q0` deben coincidir con `pose0`
- `p1, q1` deben coincidir con `pose1`
- `p2, q2` deben coincidir con el inicio del segundo tramo, o sea `pose1`
- `p3, q3` deben coincidir con `pose2`

================================================================================

Primero hay que activar:

Despues implementar:

  std::pair<tf2::Vector3, tf2::Quaternion>
  ComputeNextCartesianPose(const Eigen::Matrix4d &pose_0,
                           const Eigen::Matrix4d &pose_1,
                           const Eigen::Matrix4d &pose_2,
                           double tau,
                           double T,

Esta funcion debe devolver la pose cartesiana suavizada para el movimiento:

  P0 -> P2 pasando por P1

================================================================================
12. BUCLE TEMPORAL Y PUBLICACION
================================================================================

La generacion completa hace lo siguiente:

1. Recorre `t` desde `-T` hasta `T` con paso `sample_time`.
2. Calcula `p_interp` y `q_interp` con `ComputeNextCartesianPose(...)`.
3. Convierte el quaternion a `roll, pitch, yaw`.
4. Guarda una linea CSV con:
   `t, X, Y, Z, roll, pitch, yaw`
5. Construye una pose deseada del efector final en KDL.
6. Resuelve IK para obtener las articulaciones.
7. Rellena `trajectory_msg.points`.
8. Publica la trayectoria solo cuando haya subscriber.

El nodo publica en:

  /r6bot_controller/joint_trajectory

Comportamientos destacados:
- si no se generan puntos validos, el programa termina con error
- espera a que haya subscriber antes de publicar
- la cabecera se publica con `now + 0.2 s` para dar margen al controlador
